SaaS o servidor propio

Necesitamos entender cómo funciona hoy su infraestructura y su operación para dimensionar bien las dos alternativas: mantener el sistema como servicio mensual, o instalarlo en sus servidores.

Tres bloques, 52 preguntas. Los responde gente distinta y ninguno necesita esperar a los otros: el primero lo contesta TI, el segundo y el tercero jefatura.

Las 16 marcadas «Necesario para costear» son las que pueden cambiar el alcance o el esfuerzo. Las demás ayudan a diseñar mejor, pero no bloquean una primera estimación. Si algo no lo saben todavía, dejarlo en blanco es más útil que una aproximación.

Tecnología

Cómo funciona hoy su infraestructura, para saber qué implicaría instalar el sistema en sus servidores.

Responde: TI

Servidores

  1. ¿Dónde correrían una aplicación web como esta?
    Servidores propios, máquinas virtuales, Azure u otro.
  2. ¿Usan contenedores o instalan las aplicaciones directo en el servidor?
    Docker, Kubernetes u otro.
  3. ¿Qué sistema operativo usan en esos servidores?
  4. ¿Pueden instalar Node.js, o ya lo tienen disponible?
    Si ya lo tienen, indicar la versión.
  5. ¿Cómo publican hoy una aplicación para que sea accesible desde internet?
    El sistema recibe los mensajes de WhatsApp por una llamada entrante, así que necesita una dirección pública.
  6. ¿Qué revisiones o autorizaciones piden para publicar algo hacia afuera?

Base de datos

  1. ¿Qué motor de base de datos usan?
    SQL Server, PostgreSQL, Oracle u otro.
  2. ¿Quién administra las bases de datos?
    Equipo interno, proveedor externo, el mismo equipo de desarrollo.
  3. ¿Qué política de respaldos aplican a un sistema como este?

Archivos

  1. ¿Dónde guardan hoy los archivos que genera una aplicación?
    Carpeta de red, Azure Blob, SharePoint u otro.
  2. ¿Hay límite de espacio o tiempo de conservación?
    Cada visita puede traer tres fotos de teléfono.

Inteligencia artificial

  1. ¿Tienen Azure OpenAI habilitado?
  2. ¿Hay política sobre qué modelos de IA se pueden usar?
  3. ¿Los datos deben quedar en alguna región en particular?
  4. ¿Pueden salir datos de la empresa hacia un servicio externo para ser procesados?
    Hoy el audio del zonal y el nombre del agricultor se procesan fuera de la red.
  5. ¿Quién autoriza cambiar de modelo, y cuánto suele demorar?

WhatsApp

  1. ¿El número debe ser corporativo?
  2. ¿Tienen una cuenta de WhatsApp Business verificada a nombre de la empresa?
    WhatsApp siempre pasa por Meta o por un proveedor: no se puede instalar en un servidor propio.
  3. ¿Hay restricciones internas para usar WhatsApp en comunicaciones de la empresa?

Usuarios y accesos

  1. ¿Prefieren que entren con su cuenta de Microsoft o con un usuario propio del sistema?
    Hoy el sistema usa usuario y contraseña propios.
  2. ¿Los zonales tienen cuenta corporativa y la usan desde el teléfono?
  3. ¿Exigen segundo factor para sistemas internos?

Integración con el SIA

  1. ¿El SIA tiene API, base consultable, o solo permite exportar a Excel?
    Hoy los agricultores y lotes se cargan desde un Excel exportado.
  2. ¿Quién mantiene el SIA?
  3. ¿Cuánto suele demorar una solicitud de cambio ahí?
  4. ¿Necesitan que la visita quede registrada también en el SIA?

Soporte y operación

  1. ¿Quién operaría el sistema una vez instalado?
    Su equipo, nosotros, o compartido.
  2. ¿Tienen mesa de ayuda?
  3. Si un zonal manda un audio y no recibe respuesta, ¿a quién debería avisar?
  4. ¿Qué piden para poner un sistema en producción?
    Pruebas, documentación, revisión de seguridad, ambiente de pruebas separado.

Datos personales

  1. ¿Tienen política de tratamiento de datos personales que debamos cumplir?
    El sistema guarda nombre, teléfono y observaciones del campo de cada agricultor.
  2. ¿Cuánto tiempo debe conservarse el historial de un agricultor?
  3. ¿Qué pasa con esos datos cuando termina el contrato?
